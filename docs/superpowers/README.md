# Design documents

The specs and plans this tool was built from, kept because the argument for urtext is
mostly in them: what was measured, what was ruled, and what turned out to be wrong.

They are working documents, not polished writing. Corrections are appended rather than
folded in, so a claim that moved can be seen moving — several of them record a
conclusion being overturned by a measurement taken after the fact.

## Two things to know before reading

**Pull request numbers in these documents are not this repository's pull requests.**
The plans cite predecessors as "PR #1", "PR #2", "PR #10", and so on. Those numbers
refer to the private repository this project was developed in, which this one does not
descend from. In *this* repository they resolve to entirely different pull requests, or
to none. Read them as ordering — which plan preceded which — and not as links.

Leaving stale citations in a project whose own thesis is citation rot would be a poor
joke, so: they are stale, they are named as stale here, and the documents themselves are
left as they were written rather than quietly rewritten to point somewhere plausible.

**A private codebase these documents measure against is called "the reference
repository".** It is a real application, and the measurements taken from it are exact —
file counts, citation counts, the precision figures. Only the identifiers are removed.
Where a document compares two repositories, the other one is this one.
